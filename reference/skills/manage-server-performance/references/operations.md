# Operations reference

## CPU and thermal

Inventory with `lscpu`, `cpupower frequency-info`, `cpupower idle-info`, `cat /proc/cmdline`, and `for p in /sys/devices/system/cpu/cpufreq/policy*; do printf '%s ' "$p"; cat "$p/scaling_driver" "$p/scaling_governor" "$p/scaling_min_freq" "$p/scaling_max_freq"; done`. Check EPB at `/sys/devices/system/cpu/cpu*/power/energy_perf_bias`, turbo at `/sys/devices/system/cpu/intel_pstate/no_turbo`, coretemp readings and thermal throttle counters. The CPU's observed passive `intel_cpufreq` uses generic governors; do not assume active-mode EPP semantics apply. CPU frequency limits are requests, not proof of physical clocks or actual performance; validate using a representative load and appropriate measurements. Deep idle states can affect latency independently of the requested minimum. Thermal and power limits still apply.

The local oneshot `/etc/systemd/system/server-cpu-performance.service` runs `/usr/local/sbin/server-cpu-performance` at boot. It sets a 2.4 GHz floor and EPB 0 where supported, leaves governor and boost untouched, and skips policies with a maximum below 2.4 GHz. Check systemd status and all policies, and inspect for conflicts before modifying it. Baseline at deployment was 1.2 GHz and EPB 7. Revert live and at boot with `systemctl disable --now server-cpu-performance.service`, then write `1200000` to each `/sys/devices/system/cpu/cpufreq/policy*/scaling_min_freq` and `7` to each `/sys/devices/system/cpu/cpu[0-9]*/power/energy_perf_bias`. Confirm that original values still apply before restoring them. Stopping the oneshot alone does not restore settings. Hardware/driver changes require reevaluation; persistence has not been verified through a reboot.

## Storage

Use `lsblk -o NAME,MODEL,SIZE,TYPE,ROTA,TRAN,FSTYPE,MOUNTPOINTS`, `findmnt /`, `df -hT`, `pvs`, `vgs`, `lvs`, `lsblk -D`, `systemctl status fstrim.timer`, and `smartctl -H -A -i /dev/sda` after confirming the device. Check `journalctl -k` for storage faults without exposing unrelated logs. Examine `/sys/block/DEVICE/queue/{scheduler,read_ahead_kb,write_cache}`. The SSD is a single point of failure; SMART pass is not a backup and monitoring does not establish that remote alerts are delivered. The scheduler, TRIM, read-ahead, cache and filesystem settings should be changed only with workload-specific justification. Never disable flushes or alter disk write-cache durability merely for benchmark gains.

## Virtualization and networking

Check `/dev/kvm`, `lsmod`, `qemu-system-x86_64 --version`, `qemu-img --version`, `passt --version`, and package status. Preserve the active network, SSH, and firewall. No libvirt daemon, bridge, guest, or non-root group membership is implied by QEMU installation. QEMU native `-nic passt,model=virtio-net-pci` can spawn passt; confirm supported options against the installed version. A paused disposable QMP test previously confirmed KVM and passt attachment, but not guest DHCP, DNS, routing, throughput, or external access. Test those in an appropriate disposable guest when one is available. Explicitly configure guest port forwarding and firewall only when requested. `passt` noted no IPv6 DNS server; assess actual resolver configuration before changes.

## Locale and terminals

Inspect `locale`, `locale charmap`, `locale -a`, `localectl status`, `/etc/locale.conf`, `/etc/default/locale`, systemd environment, and SSH `sshd -T` AcceptEnv rules. `LC_ALL` overrides per-category variables and `LANG`; SSH clients may supply `LANG`/`LC_*`, and existing sessions and services retain inherited environments. Preserve intentional client and application locales. Ubuntu's `/etc/default/locale` is a symlink to `/etc/locale.conf` on this host; use `update-locale` after confirming the desired locale exists. Do not globally set `LC_ALL`, force a TUI's UTF switch, edit SSH configuration or restart SSH simply to silence a warning. Test a fresh PAM login with a clean environment, plus the affected application's actual launch path. `env -i ... bash` by itself is not a PAM login and need not inherit the system locale. For a running shell, `export LANG=en_US.UTF-8; unset LC_ALL` helps only if no conflicting `LC_CTYPE` remains; inspect before modifying user preferences. If the affected program still fails, identify its launcher and effective environment rather than guessing.

## Monitoring and validation

`systemctl is-system-running`, `systemctl is-active ssh nginx`, pressure files under `/proc/pressure`, `free -h`, `uptime`, and existing `sysstat`/`sar` data offer a low-impact baseline. Compare before/after and note confounders; do not imply causation or measured gains without tests. After package changes check `dpkg --audit`. Update the JSON tracker with ISO timestamps, scope, prior/new settings, evidence, persistence, rollback, and remaining uncertainty; verify it parses and do not invent historical results.
